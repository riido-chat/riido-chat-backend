# OpenAI 임베딩 모델·차원 비교 실험 v1

## 결론

현재 MVP의 기준선인 **A: `text-embedding-3-large` / 1536차원**을 유지한다.

- A는 현재 서비스가 실제 사용하는 Hybrid Search에서 Recall@5 `96.67%`, Recall@10
  `100%`를 기록했다.
- D(`large` / 768)는 A와 Recall@1·3·5·10 및 MRR이 같고 원시 벡터 크기는 절반이지만,
  API 비용은 A와 같고 현재 142개 Chunk에서는 저장공간 절감의 실익이 작다.
- B(`small` / 1536)는 임베딩 API 비용이 A보다 약 `84.62%` 낮고 nDCG@10은 비슷했지만,
  우선 지표인 Hybrid Recall@5가 `96.67%`에서 `92.22%`로 하락했다.
- C(`large` / 3072)는 A보다 품질이 좋아지지 않았고 원시 벡터 크기만 2배가 됐다.
- E(`small` / 768)는 B와 API 비용이 같지만 주요 검색 지표가 전반적으로 더 낮았다.

따라서 지금은 운영 임베딩 모델·차원과 DB 스키마를 변경하지 않는다. 데이터 규모가 크게
증가해 임베딩 비용이 실제 운영 부담이 되면 B를 비용 절감 후보로 다시 검토하고, 저장공간이나
벡터 검색 성능이 병목이 되면 D를 별도 pgvector 환경에서 검증한다.

## 실험 목적

동일한 문서·질문·BM25·RRF 조건에서 모델 크기와 출력 차원이 다음 항목에 미치는 영향을
비교했다.

- Vector Search와 Hybrid Search 검색 품질
- OpenAI 임베딩 API 비용
- 문서 벡터의 원시 저장 크기

## 평가 방법

- 평가일: 2026-09-08
- 코드 기준: Git commit `57b13e1d6efcb5d594d46acd524b54238f9417c9`
- Corpus: 현재 `clean_manifest.json`으로 생성한 39개 문서, 142개 Chunk
- 평가셋: 현재 `ground_truth.json`의 30문항, 정답 Section 38개
- Vector 후보: 각 후보의 문서·질문 임베딩을 이용한 메모리 내 cosine Top-10
- BM25 후보: 현재 `BM25Retriever`의 Top-10
- Hybrid 후보: 현재 제품의 RRF 결합 로직과 `k=60`, 최종 Top-10
- 우선 판단 지표: 실제 답변 문맥 범위에 맞춘 Hybrid Recall@5
- 보조 지표: Recall@1·3·10, MRR@10, nDCG@10

운영 DB와 ACTIVE index는 사용하거나 변경하지 않았다. 실험용 Chunk ID를 manifest 순서대로
부여해 현재 RRF 로직의 결정적 tie-break 조건만 재현했다.

## 비용과 저장 부담

모든 후보는 동일한 입력 `37,744 tokens`를 사용했고 후보마다 API 요청 3회가 발생했다.
가격은 실험일 기준 OpenAI 공식 가격인 large `$0.13 / 1M tokens`, small
`$0.02 / 1M tokens`를 적용했다.

| 후보 | 실제 입력 Token | 추정 API 비용 | A 대비 비용 | 원시 문서 벡터 크기 | A 대비 크기 |
| --- | ---: | ---: | ---: | ---: | ---: |
| **A: large / 1536** | 37,744 | $0.00490672 | 100% | 872,448 bytes | 100% |
| B: small / 1536 | 37,744 | $0.00075488 | 15.38% | 872,448 bytes | 100% |
| C: large / 3072 | 37,744 | $0.00490672 | 100% | 1,744,896 bytes | 200% |
| D: large / 768 | 37,744 | $0.00490672 | 100% | 436,224 bytes | 50% |
| E: small / 768 | 37,744 | $0.00075488 | 15.38% | 436,224 bytes | 50% |

- 이번 5개 후보 실험의 총 추정 API 비용: **$0.01622992**
- 출력 차원은 OpenAI의 token 기반 API 가격을 바꾸지 않는다.
- 저장 크기는 `Chunk 수 × 차원 × float32 4 bytes`로 계산한 원시 벡터 값이다.
  PostgreSQL row와 pgvector index의 실제 부가 공간은 포함하지 않았다.

## 해석할 때의 한계

- 30문항, 정답 Section 38개의 작은 고정 평가셋 결과이므로 일반적인 모델 우열로 확대하면
  안 된다.
- 실제 PostgreSQL/pgvector를 사용하지 않았으므로 DB 저장 크기, 인덱스 크기, 검색 지연,
  recall 차이는 측정하지 않았다.
- 기록된 embedding 응답 시간은 후보별 1회 실행값이라 네트워크 상태와 서버 상황의 영향을
  받는다. 안정적인 latency benchmark로 사용하지 않는다.
- 이번 실험은 Retrieval만 비교했으며 최종 답변 생성 품질은 평가하지 않았다.
- 현재 Corpus가 작아 후보 간 절대 비용과 저장공간 차이는 운영 의사결정을 바꿀 정도로 크지
  않다.

## 후속 판단 기준

1. 현재 MVP는 A를 유지한다.
2. 문서량·재색인 빈도가 증가해 임베딩 비용이 문제가 되면 B를 동일 평가셋으로 재검증한다.
3. DB 벡터 저장량이나 pgvector 검색 시간이 병목이 되면 별도 실험 index에서 A와 D를
   비교한다.
4. 평가셋을 확장한 뒤에만 모델 교체 결정을 다시 연다.
